# Desktop Vision - 视觉AI桌面控制（增强版）

## 核心原则

**永远优先使用视觉理解，OCR 仅作为最终降级方案。**

```
截图 → 直接看图(视觉AI) → 理解UI/布局/颜色/状态/图标 → 决策 → 执行操作 → 验证
```

OCR只能提取文字，会丢失80%以上的信息（UI结构、按钮状态、颜色、图标、窗口层级等）。视觉AI能完整理解屏幕上的一切。因此视觉AI是主方案，OCR仅作最终降级。

| 脚本 | 路径 | 用途 |
|-----|------|------|
| **vision.py** | `$env:TEMP\vision.py` | 主力工具：截图+鼠标键盘控制+窗口信息+像素检测 |
| **desktop_monitor.py** | `$env:TEMP\desktop_monitor.py` | 备用方案：OCR文字识别+桌面监控 |

## 完整命令参考

### 基础操作

```bash
python "$env:TEMP\vision.py" screenshot                                    # 全屏截图
python "$env:TEMP\vision.py" screenshot <x> <y> <w> <h>                   # 区域截图(ROI)
python "$env:TEMP\vision.py" click <x> <y> [left|right]                   # 单击(支持左/右键)
python "$env:TEMP\vision.py" doubleclick <x> <y>                          # 双击
python "$env:TEMP\vision.py" rightclick <x> <y>                           # 右键点击
python "$env:TEMP\vision.py" move <x> <y>                                 # 移动鼠标
python "$env:TEMP\vision.py" type "<text>"                                # 输入文本(自动支持中文)
python "$env:TEMP\vision.py" key <key_name>                               # 按键: Enter, Tab, Escape等
python "$env:TEMP\vision.py" key <k1> <k2>                                # 组合键: ctrl c, alt tab等
python "$env:TEMP\vision.py" scroll <amount>                              # 滚轮: 正=上, 负=下
python "$env:TEMP\vision.py" drag <fx> <fy> <tx> <ty> [duration]         # 拖拽: 从(fx,fy)到(tx,ty)
```

### 高级操作

```bash
python "$env:TEMP\vision.py" wait <seconds>                               # 显式等待
python "$env:TEMP\vision.py" mousepos                                     # 获取鼠标当前位置
python "$env:TEMP\vision.py" activewin                                    # 获取当前活动窗口信息
python "$env:TEMP\vision.py" screeninfo                                   # 获取显示器信息(多显示器)
python "$env:TEMP\vision.py" pixel <x> <y>                                # 获取指定像素颜色
```

### 返回值格式

| 命令 | 返回JSON |
|------|---------|
| screenshot | `{"path":"...", "width":3200, "height":2000, "mouse":[x,y], "time":"HH:mm:ss", "region":null}` |
| activewin | `{"title":"窗口标题", "hwnd":12345, "rect":[L,T,R,B], "width":W, "height":H}` |
| screeninfo | `{"monitors":[...], "count":N}` |
| mousepos | `{"x":100, "y":200}` |
| pixel | `{"x":100, "y":200, "r":255, "g":128, "b":0, "hex":"#ff8000"}` |

## 增强工作流

### 核心循环：感知-决策-执行-验证（PDCA）

```
┌─────────────────────────────────────────────┐
│  1. 感知(Perceive): 截图 + 视觉分析         │
│  2. 决策(Decide):  判断当前状态 → 选择动作  │
│  3. 执行(Act):     执行操作命令             │
│  4. 验证(Check):   截图确认操作结果         │
│         ↓ 验证失败 → 重试/降级/回滚         │
│         ↓ 验证成功 → 下一步或完成           │
└─────────────────────────────────────────────┘
```

### 第一步：感知 - 截取与分析

```bash
python "$env:TEMP\vision.py" screenshot
```

然后使用 `Read` 工具读取截图路径，用视觉AI分析。

**分析报告必须包含：**
- **环境上下文**：当前活动窗口、桌面布局、多窗口层级关系
- **UI结构**：窗口标题、菜单栏、工具栏、内容区、状态栏
- **交互元素**：按钮（含状态：启用/禁用/悬停）、输入框、下拉框、复选框、标签页
- **视觉特征**：颜色编码（成功绿/警告黄/错误红）、图标含义、进度指示器
- **文字内容**：作为辅助信息，标注关键文字及其位置
- **异常信号**：弹窗、错误提示、加载动画、遮罩层

### 第二步：决策 - 状态判断与动作选择

根据视觉分析结果，判断当前处于哪个状态，选择对应操作：

| 当前状态 | 判断依据 | 典型动作 |
|---------|---------|---------|
| 目标窗口未打开 | 截图中无目标窗口 | 启动应用/切换窗口 |
| 目标元素不可见 | 元素在视口外 | 滚动/切换标签页 |
| 等待加载中 | 进度条/加载动画/遮罩层 | 等待后重新截图 |
| 弹窗/对话框遮挡 | 模态对话框在最前层 | 处理弹窗(确认/取消/关闭) |
| 目标元素可见且可交互 | 元素处于启用状态 | 执行目标操作 |
| 操作完成 | 出现成功提示/界面变化 | 验证结果/进入下一步 |
| 操作失败 | 出现错误提示/界面未变 | 重试/降级/报错 |

### 第三步：执行 - 操作命令

根据决策结果执行操作，操作时遵循以下原则：

1. **操作前必截图** — 确保基于最新状态操作
2. **操作后必等待** — 给界面响应时间（0.3-2秒）
3. **关键操作前备份** — 对可能破坏性操作先记录当前状态
4. **一次一个操作** — 避免操作叠加导致状态混乱

### 第四步：验证 - 结果确认

```bash
python "$env:TEMP\vision.py" screenshot
```

再次截图验证操作结果，确认：
- 预期变化是否发生
- 是否出现意外弹窗或错误
- 界面是否处于预期状态

## 多步骤复杂任务执行框架

### 任务分解策略

对于复杂任务，采用**分层分解**方法：

```
用户任务
├── 阶段1: 准备环境
│   ├── 步骤1.1: 打开目标应用
│   └── 步骤1.2: 确认应用就绪
├── 阶段2: 执行核心操作
│   ├── 步骤2.1: 导航到目标位置
│   ├── 步骤2.2: 执行操作A
│   └── 步骤2.3: 执行操作B
└── 阶段3: 验证与收尾
    ├── 步骤3.1: 确认操作结果
    └── 步骤3.2: 保存/关闭
```

### 状态追踪机制

在执行多步骤任务时，维护一个**任务状态上下文**：

```
任务状态上下文:
- 当前阶段: 阶段2
- 当前步骤: 2.1
- 已完成步骤: [1.1, 1.2]
- 重试计数: {2.1: 1}  # 步骤2.1已重试1次
- 关键数据: {目标文件名: "report.xlsx", 目标路径: "C:\Users\..."}
- 回滚点: 阶段1完成时的截图路径
```

### 条件分支逻辑

根据视觉分析结果动态选择执行路径：

```
截图分析 → 目标元素是否存在？
├── 是 → 元素是否可交互？
│   ├── 是 → 执行点击操作
│   └── 否(灰色/禁用) → 是否有前置条件？
│       ├── 是 → 先完成前置条件
│       └── 否 → 报告无法操作
└── 否 → 是否需要滚动？
    ├── 是 → 滚动后重新检查
    └── 否 → 是否在另一个标签页？
        ├── 是 → 切换标签页
        └── 否 → 报告元素不存在
```

### 跨应用工作流

涉及多个应用协作的复杂操作：

```
1. 在应用A中获取数据 → 截图读取信息
2. 切换到应用B → Alt+Tab / 点击任务栏
3. 在应用B中输入数据 → 粘贴/输入
4. 返回应用A确认 → Alt+Tab
5. 验证两端状态一致
```

**关键**：每次切换应用后必须重新截图确认焦点窗口。

## 动态环境适应性

### 窗口焦点管理

```bash
# 获取当前活动窗口
python "$env:TEMP\vision.py" activewin
# 返回: {"title":"记事本", "hwnd":12345, "rect":[100,100,800,600], ...}

# 切换窗口策略
python "$env:TEMP\vision.py" key alt tab          # Alt+Tab切换
python "$env:TEMP\vision.py" hotkey alt tab        # 等效写法
```

**窗口切换决策树：**
1. 先用 `activewin` 确认当前窗口
2. 如果不是目标窗口 → 尝试 Alt+Tab
3. 如果Alt+Tab后仍不是 → 截图查看任务栏，点击目标应用图标
4. 如果任务栏也没有 → 启动应用

### 智能等待策略

| 等待场景 | 等待方式 | 典型时长 |
|---------|---------|---------|
| 点击后界面响应 | `wait 0.5` | 0.3-1秒 |
| 应用启动 | `wait 3` + 截图检查 | 2-10秒 |
| 文件加载/保存 | `wait 2` + 截图检查 | 1-5秒 |
| 网络请求 | `wait 3` + 循环截图检查 | 3-30秒 |
| 动画/过渡效果 | `wait 1` | 0.5-2秒 |

**轮询等待模式**（等待某个状态出现）：
```
循环(最多N次):
  1. 截图
  2. 视觉分析是否达到目标状态
  3. 如果是 → 继续
  4. 如果否 → wait 1秒 → 回到步骤1
  5. 超过N次 → 报告超时
```

### 多显示器支持

```bash
# 获取显示器信息
python "$env:TEMP\vision.py" screeninfo
# 返回: {"monitors":[{"width":3200,"height":2000,"x":0,"y":0,"is_primary":true}], "count":1}
```

- 截图默认捕获所有显示器的合并画面
- 坐标系统跨越所有显示器（副屏x可能为负值或大于主屏宽度）
- 操作特定显示器上的窗口时，坐标直接可用

### DPI缩放适配

- Windows缩放比例可能导致坐标偏移
- 如果发现点击位置与预期不符：
  1. 用 `pixel` 命令检查目标位置的实际颜色
  2. 对比视觉分析中的预期颜色
  3. 如果偏移，按DPI比例调整坐标

## 视觉识别优化策略

### 分层分析流程

```
第一层: 全局扫描（全屏截图）
  → 识别窗口布局、活动应用、整体状态
  → 定位目标区域的大致范围

第二层: 区域聚焦（ROI截图）
  → 对目标区域进行精细分析
  → python "$env:TEMP\vision.py" screenshot <x> <y> <w> <h>
  → 识别具体UI元素、文字、状态

第三层: 像素验证（关键点检查）
  → python "$env:TEMP\vision.py" pixel <x> <y>
  → 验证特定位置的颜色是否符合预期
  → 快速确认按钮状态、选中状态等
```

### 元素定位策略

按优先级使用以下方法定位UI元素：

| 优先级 | 策略 | 适用场景 | 可靠性 |
|-------|------|---------|-------|
| 1 | **视觉特征定位** | 按钮图标、颜色标识、独特形状 | ★★★★★ |
| 2 | **文字标签定位** | 按钮文字、标签文字、标题 | ★★★★ |
| 3 | **布局关系定位** | "在XX按钮右边"、"标题下方" | ★★★ |
| 4 | **固定坐标定位** | 菜单固定位置、工具栏图标 | ★★ |

**定位精度提升技巧：**
- 先定位大区域（窗口/面板），再在区域内定位具体元素
- 利用对齐关系：按钮通常在同一行/列
- 利用颜色区分：活动标签页高亮、选中项蓝色背景
- 利用状态指示：勾选框打勾、单选按钮填充

### 置信度决策机制

对视觉分析结果进行置信度评估：

| 置信度 | 判断 | 行动 |
|-------|------|------|
| ≥90% | 非常确定 | 直接执行操作 |
| 70-89% | 较为确定 | 执行操作，但截图验证 |
| 50-69% | 不太确定 | 使用ROI截图放大分析，或用pixel验证 |
| <50% | 不确定 | 重新截图分析，或向用户确认 |

### 变化检测

操作前后对比截图，检测关键变化：

```
操作前截图 → 执行操作 → 操作后截图
对比分析:
- 新出现的元素（弹窗、提示、高亮）
- 消失的元素（加载动画、对话框）
- 状态变化（按钮从禁用变启用、进度条前进）
- 位置变化（滚动、页面切换）
```

## 异常处理机制

### 错误分类与处理

| 错误类型 | 识别特征 | 处理策略 |
|---------|---------|---------|
| **元素未找到** | 截图中无目标元素 | 滚动查找→切换标签→扩大搜索范围→报错 |
| **元素不可交互** | 元素灰色/禁用/被遮挡 | 查找前置条件→关闭遮挡弹窗→等待加载 |
| **意外弹窗** | 模态对话框、确认框、错误提示 | 读取弹窗内容→按策略处理(确认/取消/关闭) |
| **操作无效果** | 点击后界面无变化 | 重试点击→检查焦点→尝试键盘操作 |
| **加载超时** | 长时间显示加载状态 | 增加等待→刷新页面→重启应用 |
| **截图异常** | 黑屏/空白/防截图保护 | 激活窗口→切换到前台→降级为OCR |
| **坐标偏移** | 点击位置与预期不符 | DPI校准→使用相对定位→pixel验证 |
| **窗口丢失** | 目标窗口消失/最小化 | Alt+Tab恢复→从任务栏重新打开 |
| **中文输入失败** | 输入内容不正确 | vision.py已自动使用剪贴板方式输入中文 |

### 重试策略

```
重试策略（指数退避）:
第1次重试: 等待 1秒
第2次重试: 等待 2秒
第3次重试: 等待 4秒
最多重试 3 次，超过后进入降级流程
```

**重试前必须重新截图**，因为界面状态可能已变化。

### 降级链

当视觉方式无法完成任务时，按以下顺序降级：

```
视觉AI分析(主力)
  ↓ 失败
ROI区域截图 + 放大分析
  ↓ 失败
pixel颜色验证 + 布局推断
  ↓ 失败
OCR文字识别(desktop_monitor.py)
  ↓ 失败
MCP工具辅助(desktop-pro窗口管理/puppeteer浏览器)
  ↓ 失败
向用户报告，请求手动干预
```

### 状态恢复

当操作失败需要回滚时：

1. **记录回滚点**：在关键操作前截图保存当前状态
2. **回滚操作**：按逆向顺序撤销已执行的操作
3. **恢复验证**：截图确认已恢复到回滚点状态
4. **常见回滚操作**：
   - 关闭意外打开的弹窗：`Escape` 键
   - 取消未完成的操作：`Ctrl+Z` 撤销
   - 恢复窗口状态：重新截图确认

## 复杂场景操作模式

### 场景1：表单自动填写

```
1. 截图 → 识别表单结构（输入框数量、类型、标签）
2. 逐字段填写：
   a. 点击目标输入框
   b. 清除已有内容(Ctrl+A → Delete)
   c. 输入目标文本
   d. 截图验证输入结果
   e. 移至下一字段(Tab键或点击)
3. 处理下拉选择：
   a. 点击下拉框
   b. wait 0.5
   c. 截图查看选项列表
   d. 点击目标选项
4. 处理复选框/单选：
   a. 截图确认当前状态
   b. 仅在需要切换时点击
5. 提交表单：
   a. 截图确认所有字段正确
   b. 点击提交按钮
   c. 截图验证提交结果
```

### 场景2：文件操作工作流

```
1. 打开文件管理器/应用
2. 导航到目标路径：
   a. 地址栏点击(Ctrl+L)
   b. 输入路径
   c. 按Enter
   d. 截图确认到达目标位置
3. 定位目标文件：
   a. 截图查看文件列表
   b. 如未找到 → 滚动查找
   c. 如仍未找到 → 搜索(Ctrl+F)
4. 执行文件操作：
   a. 右键点击文件 → rightclick <x> <y>
   b. 截图查看上下文菜单
   c. 点击目标操作(复制/重命名/删除等)
5. 确认操作结果
```

### 场景3：跨应用数据传递

```
1. 源应用中选取数据：
   a. 截图确认源应用状态
   b. 选中目标内容(Ctrl+A 或拖选)
   c. 复制(Ctrl+C)
2. 切换到目标应用：
   a. Alt+Tab 或点击任务栏
   b. 截图确认目标应用已激活
3. 粘贴数据：
   a. 点击目标输入位置
   b. Ctrl+V 粘贴
   c. 截图验证粘贴结果
4. 返回源应用确认(如需要)
```

### 场景4：自动化监控与响应

```
1. 初始截图 → 建立基线状态
2. 循环监控：
   a. 定时截图
   b. 对比基线检测变化
   c. 如检测到目标变化 → 执行响应操作
   d. 如未检测到 → 继续等待
3. 响应操作：
   a. 截图分析变化内容
   b. 根据变化类型选择操作
   c. 执行操作后截图确认
4. 超时处理：
   a. 达到最大监控时间 → 报告超时
   b. 达到最大变化次数 → 停止监控
```

### 场景5：安装向导/多步对话框

```
1. 截图识别当前向导步骤
2. 读取步骤指示器(如"步骤2/5")
3. 分析当前页面的选项和输入
4. 根据用户需求选择/填写
5. 点击"下一步"/"Next"
6. wait 1 → 截图确认进入下一步
7. 循环直到完成
8. 处理意外弹窗(许可证协议、更新提示等)
```

### 场景6：右键菜单与上下文操作

```
1. 对目标元素执行右键点击：
   python "$env:TEMP\vision.py" rightclick <x> <y>
2. wait 0.5 → 截图查看上下文菜单
3. 在菜单中定位目标选项
4. 点击目标选项
5. wait 0.5 → 截图确认操作结果
6. 如果出现子菜单 → 继续在子菜单中定位
```

## 坐标系统

- 屏幕原点 (0,0) 在**左上角**
- X轴向右增长，Y轴向下增长
- 多显示器：坐标跨越所有显示器，副屏坐标可能为负值或超出主屏范围
- 从视觉分析中获取的坐标可直接用于点击
- DPI缩放可能导致偏移，如遇偏移用 `pixel` 命令校验

## MCP服务器协同策略

| MCP | 协同场景 | 优先级 |
|-----|---------|-------|
| **desktop-pro** | 窗口管理(激活/最小化/关闭)、进程控制 | 视觉操作前的窗口准备 |
| **puppeteer** | 浏览器内精确操作(DOM选择器) | 浏览器场景优于视觉点击 |
| **desktop-commander** | 启动应用、执行系统命令 | 非GUI后台操作 |
| **filesystem** | 文件读写、目录操作 | 文件操作优于视觉方式 |

**协同原则：**
- GUI操作 → 优先使用本技能视觉方式
- 浏览器内操作 → 优先puppeteer（更精确），视觉方式作为备选
- 非GUI操作 → 优先MCP工具（更可靠）
- 窗口管理 → 先用desktop-pro准备环境，再用视觉操作

## 操作安全与约束

1. **每次操作前先截图** — 桌面状态可能已变化
2. **操作后截图验证** — 确认操作效果
3. **破坏性操作二次确认** — 删除、覆盖、发送等操作前截图确认目标
4. **防截图保护** — 金融软件等有反截图机制，会显示黑屏，需降级处理
5. **尊重用户隐私** — 截图可能包含敏感信息，不主动记录或传播
6. **延迟适当等待** — 点击/输入后等待0.3-1秒让界面响应
7. **FailSafe保护** — 鼠标移到屏幕角落可紧急停止所有操作
8. **操作频率限制** — 避免过快连续操作导致系统无响应
9. **中文输入** — vision.py自动检测非ASCII字符，通过剪贴板粘贴方式输入

## 错误处理速查表

| 问题 | 识别方式 | 解决方案 |
|-----|---------|---------|
| 截图为黑屏/空白 | 视觉分析无内容 | `activewin`检查窗口 → 激活目标窗口 → 重试截图 |
| 目标元素找不到 | 截图中无目标 | 滚动页面 → 切换标签页 → ROI放大分析 → OCR降级 |
| 点击位置偏移 | 操作后截图显示点错位置 | `pixel`验证坐标 → DPI校准 → 使用视觉特征重新定位 |
| 防截图保护触发 | 截图为纯黑/遮挡 | 该应用无法视觉操作 → 降级为API/手动 |
| 弹窗遮挡操作 | 截图显示模态对话框 | 读取弹窗内容 → 按策略处理(确认/取消/关闭) |
| 操作无响应 | 操作前后截图无变化 | 重新截图 → 检查焦点 → 重试 → 尝试键盘替代 |
| 窗口最小化 | 截图中无目标窗口 | `activewin`确认 → Alt+Tab恢复 → 任务栏点击 |
| 加载卡住 | 长时间显示加载状态 | 等待重试 → 刷新操作 → 重启应用 |
| 输入框无法输入 | 输入后截图无文字 | 确认焦点在输入框 → Ctrl+A清除 → 重新输入 |
| 下拉选项不匹配 | 选项列表中无目标 | 搜索过滤 → 滚动查找 → 手动输入 |
