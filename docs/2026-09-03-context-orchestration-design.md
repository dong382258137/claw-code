# 上下文托管于管理脑（Context Steward）设计 v1

> 状态：定稿 v1（用户五项裁决 2026-09-04）· 前置：双大脑 v5.1（[2026-09-03-dual-brain-optimization-design.md](./2026-09-03-dual-brain-optimization-design.md)，brain-daemon 落地中）
> 关联：轮次感知上下文编译器（triage\_llm / sufficiency / cost\_meter / 三层注入，commit 323e06e7 起已落地执行脑侧）

## 1. 背景与北极星

**北极星**：上下文是稀缺资源，按**任务状态**按需分配。持有全局视角的管理脑（brain-daemon）在关键决策点裁决"本轮上下文配方"；执行脑只确定性执行配方。管理脑对执行脑任务执行状态可见，支持**及时纠偏**（空转/高成本/跑偏）与**及时投喂**（缺知识/缺上下文/跨会话恢复）。

**问题陈述（现状事实）**：

1. 轮次感知上下文编译器只在 turn 入口对一条用户输入做二档分类（本地 flash 单轮）——对任务阶段（侦察空转、成本超阈、未落盘、跨会话续跑）无感；细粒度信号在运行时就绪，但无决策方消费。
2. 分诊是**无状态单轮咨询**：flash 每 turn 从零判断，看不到"续跑任务""已烧 43K token"等状态。
3. 管理脑目前只有 ask\_brain（被动拉取）与 digest（会话结束聚合），缺"运行中、请求构造前"的咨询通道。
4. 本地 flash 分诊与"管理脑持全局状态"存在职责重叠——分诊本质是状态感知决策，应归管理脑。

## 2. 用户五项裁决（2026-09-04）

| # | 议题         | 裁决                                                     |
| - | ---------- | ------------------------------------------------------ |
| 1 | 介入频率       | **先做例外介入**：轻量分诊=管理脑常态职责；深度编排（资产投喂/收敛策略）仅例外触发           |
| 2 | 信任边界       | **配方是指令**：执行脑无条件按配方组装；纠错靠验证层仲裁 + 效果回流，不做执行脑侧校验         |
| 3 | 管理脑可见状态    | 管理脑应看到执行脑**任务执行状态**（turn/迭代/侦察/成本/plan），满足及时纠偏与及时投喂    |
| 4 | flash 分诊归属 | **分诊职责移交管理脑实现**（管理脑内部可用 flash 级低成本判定）；执行脑本地 flash 分诊退役 |
| 5 | 落地节奏       | 依项目架构**逐步落地**，每批次独立可验证，确保每环节有保证                        |

## 3. 目标架构

```
用户 turn 进入
   ▼
┌─ L0 请求构造（执行脑，确定性，每轮）───────────────┐
│  读 ContextStrategy(配方) → 组装层/工具/注记           │
│  字节稳定：配方 turn 级锁定，绝无迭代级变动            │
│  降级：管理脑不可用/超时 → Standard 全量(无害回退)      │
└───────────▲──────────────────────────────┘
            │ 分诊请求(输入+状态快照) / 配方响应(指令)
┌───────────┴──────────────────────────────┐
│ L1 管理脑（brain-daemon，唯一分诊方）               │
│  常态职责：轻量分诊(内部 flash 级) → tier/配方         │
│  深度编排(例外)：侦察空转/成本超阈/任务切换/跨会话恢复    │
│   → 附加 asset_hints / converge_hint               │
└───────────▲──────────────────────────────┘
            │ 状态事件（执行脑→管理脑，近实时）
┌───────────┴──────────────────────────────┐
│ L2 执行脑状态事件流（turn/迭代边界/侦察计数/成本/plan）   │
└─────────────────────────────────────────────┘
            ▲ 验证层（编译/测试/用户验收）仲裁一切
```

## 4. ContextStrategy 配方（turn 级稳定）

```json
{
  "tier": "standard",
  "layer_override": null,
  "tool_subset": null,
  "asset_hints": [],
  "converge_hint": null
}
```

- 字段语义同草案 v0.1（\[对话纪要]）：tier 兼容两档；layer\_override/tool\_subset 细粒度覆盖；asset\_hints 知识投喂；converge\_hint 收敛提示（走运行时注记通道，不进静态区）。

- 配方响应须带 `strategy_id`（可追踪/审计）与失效语义：仅对当前 turn 有效，turn 结束作废。

## 5. 分诊职责移交机制

- 执行脑 turn 入口不再本地调 flash；改为向管理脑发**分诊请求**（用户输入 + 状态快照摘要）。

- 管理脑内部实现自由（flash 级单轮判定为默认；可升级深度判定当信号触发）。

- 降级链：管理脑不可用/超时/无响应 → 执行脑回退 `Standard` 全量（与现 `CLAW_TRIAGE_MODE=off` 同语义，无害）。**不**回退本地 flash（职责已移交）。

- 执行脑侧 `triage_llm.rs` 的解析/开关语义迁往管理脑侧（brain 会话 prompt/解析）；执行脑保留 `TriageTier` 类型与配方应用逻辑。

## 6. 状态事件通道（裁决 3）

- 载体：沿用 v5.1 通信媒介（`.claw/` 共享 + bus/lane 轨迹），新增**执行脑状态事件**：`turn_started / iteration_boundary / survey_count / cost_threshold / plan_state / task_switch / session_resume`。

- 时效：turn 级秒级（深度编排判定不需要迭代级毫秒）；事件紧凑（结构化一行 JSON，避免文件膨胀；滚动保留最近 N 事件）。

- 消费：管理脑常驻订阅/轮询；事件同时作为 digest/失败签名的输入（复用，不另起炉灶）。

## 7. 信任与纠错（裁决 2）

- 配方=指令：执行脑无条件按配方组装（含 layer\_override/tool\_subset），不做本地校验。

- 纠错闭环：配方执行效果（编译/测试/验收）由验证层仲裁 → 失败签名自动记账（auto\_capture\_failure）→ 管理脑经 digest/失败模式迭代配方策略。错误配方 = 单次可归因、可回滚（turn 级作废），不扩散。

- 与 v5.1 一致：管理脑"亲自实施 + 验证层裁决"模式推广到上下文域；上下文配方是管理脑写权的一部分，风险由验证层兜底。

## 9. 成本与风险

| 项          | 评估                                              |
| ---------- | ----------------------------------------------- |
| 常态成本       | 轻量分诊从执行脑本地移到管理脑（内部 flash 级）→ 单价持平，管理脑复用状态缓存可能更省 |
| 深度编排       | 例外才触发；受 cost\_limit 约束（v5.1 既有）                 |
| 延迟         | 常态 +1 次跨进程往返（\~1s，flash 级）；可用"状态快照预判"压缩         |
| 风险① 管理脑不可用 | 降级 Standard 全量（无害）；执行脑不因分诊故障阻塞                  |
| 风险② 配方指令错误 | 验证层仲裁 + 失败签名回流；turn 级作废不扩散                      |
| 风险③ 事件通道膨胀 | 紧凑 JSON + 滚动保留 + 保留窗口上限                         |

## 10. 度量与试点

- 度量：tier 分布 / 每 turn output token / 深度介入率(<10%) / 配方采纳率 / strategy\_id 覆盖审计。

- Pilot：批次 D 先接"跨会话恢复"与"侦察空转"两触发（收益最明确、频次可控）；对照审计基线验收。

- 不显著优 → 深度编排默认关，保留手动入口（v5.1 §6 可证伪验收同款）。
