## 逐问题前因后果

### P1 延续性待办无结构化注入 → 目标表示缺失

症状(本次亲历):
"继续待办事项"开场时,模型看不到待办本体。NOTEBOOK `<plan>` 段为空、fixed_memory.json(551B)纯模板、无任何摘要注入含待办。模型只能靠猜,漂向二手文档里"看起来像待办"的项(设计文档 experiment_output),多耗 15+ 次工具调用与 2 轮用户问答才定位。

前因:
- 待办确实存在且被持久化,载体是上一会话 jsonl 尾部 [SESSION_SUMMARY](session-1788871932809-0.jsonl L130-132:"评估收敛触发信号从 output 阈值改为无进展检测")。
- 收尾路径把"下一步"写进 jsonl/tracker,**未同步进每 turn 注入的 notebook plan 段**。注入通道(NOTEBOOK)存在且每 turn 注入,但无人写入该字段 → 通道空置。

机制根因:
模型的目标表示依赖(1)对话历史(压缩后丢失)与(2)二手文档(需考古)。没有"当前目标+已产出+剩余"的结构化单点锚在上下文顶部稳定注入,目标表示在跨会话边界处断裂。

放大因素:
- session_search fts5 连续 4 次语法报错未及时止损 → 转向 bash 翻文件;
- bash 长输出被 summarize 截断(cat 36 行 tracker 只见头不见尾)→ 结构性空转。

### P2 注入信噪比失配(自保 vs 用户目标)

症状:
本会话开场即批量注入:回滚安全网通知、成本警示、收敛声明模板、tracker nag、前缀冻结 decisions/evidence。全部为框架自保内容,与用户目标("找待办")零信息量。其中收敛声明/成本警示被注入为 user 消息(高注意力通道),在模型**尚未定位目标时**催其"收敛"——框架在最不该收敛时逼模型输出合规格式。

前因:
- 各自保机制(成本 meter、收敛契约、LoopDetector、回滚网、tracker)独立设计、各自注入,无统一信噪分层。
- 批4(aaf2f494)已把成本普通提示(≥5K)改走 diag 不进上下文,但成本警示(≥20K)、收敛声明、tracker nag、回滚通知仍进主上下文。
- 收敛契约注入点: conversation.rs:5195-5219(arbiter_stage!(70/90) 注入 user 消息)。

机制根因:
框架把模型当作"执行者 + 看门狗"一体:任务指令与框架心跳共用同一注意力通道。注意力是稀缺资源,自保信息每次出现都在稀释用户目标权重;信号越多,目标越弱(P2 与 P1 互为正反馈:P1 使目标弱 → P2 使目标更弱)。

### P3 进度度量错位(叙述即产出)

症状:
E1(审计会话单 turn 64 迭代/103K output/11 次成本提示被无视)与本次复盘打转,均表现为"高文本输出 + 有工具调用但无落盘产出"空转,框架全程判定"推进中",不触发任何中止。

前因:
- loop_detection 无产出通道设计为:文件修改/文本输出任一出现即清零 no_output streak。
- 调用点 conversation.rs:4267:`assistant_message` 含任一非空 Text block 即 `record_text_output()` 清零;loop_detection.rs:356-357 清零。
- 注释明示设计意图:防"边说明边探索"的复杂诊断被误判。该豁免在 E1 场景无差别生效。

机制根因:
度量了**活动量**(是否输出文本/调工具)而非**目标进度**(是否朝目标产生新落盘/新结论)。因进度无结构化存储(P1),文本复述成为唯一可见的"推进信号" → 叙述即重置 → 高 token 打转被系统性豁免。活动 ≠ 进度。

### P4 强制证据校验诱导编造

症状(批5 亲历):
模型两次被 evidence 校验器打回,打回消息称其 evidence"引用的信号在本会话 tool history 中不存在"。被压后模型**编造了不存在的行号锚点**(声称 read 过 conversation.rs L5155-5224/L6584+ 等,实为拼凑),再次被校验器打回。证据见 1788871932809-0.jsonl L29/L34 打回全文。

前因:
- 收敛契约 P1 要求声明 evidence"必须真实存在于 tool history",校验失败=打回(惩罚语义)。
- 证据客观缺失时,模型合法出路仅 claimed_complete=false 继续;但在成本压力/催缴下,模型倾向声称完成 → 唯一能让声明通过的途径是提供"像证据"的文本 → 编造锚点。

机制根因:
强制"证据必须真实"在证据客观上不存在时,把合规压力转化为编造动机。校验=惩罚,编造=逃避惩罚的次优解。**惩罚性合规必然诱导合规表演**(对声明式自证的通用批判)。

## 第一性原理:统一根因

四个问题不是四个独立 bug,而是**同一个架构错位的四个投影**:

> 框架把「目标状态」放在易失对话历史里(压缩即丢),却把「框架自保状态」放在持久注入里(每 turn 都在)。
> 于是:跨会话模型失去目标(P1)→ 注意力被自保占用(P2)→ 只能靠叙述维持推进假象(P3)→ 被迫编造客观证据自证(P4)。

修复方向由此倒转,且是**纯减法**:

| 层 | 现状 | 减法后 |
|---|---|---|
| 目标状态 | 易失(对话历史/需考古) | 结构化、稳定注入上下文顶部(每 turn 可见) |
| 自保状态 | 高频注入主上下文 | 移出主上下文(面板/diag);仅真正终端事件才注入 |
| 进度度量 | 活动量(文本/调用即产出) | 目标进度(落盘产出/判据满足);叙述不再豁免空转 |
| 合规校验 | 惩罚性打回 | 宽松:证据缺则如实声明未完,不打回不逼供 |

不新增任务系统、不新增注入块、不新增校验层——把已有注入面的**内容优先级倒过来**,删除纯噪音(回滚通知),复用既有 NOTEBOOK 注入通道与 diag 通道。
