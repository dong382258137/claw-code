# 收敛契约：运行时语义收敛与确定性归档设计

> 日期：2026-09-05 · 状态：草案 · 上游：2026-09-03-dual-brain-architecture.md / 2026-09-03-dual-brain-optimization-design.md
> 触发背景：audit session-1788545064755（BTC 30m L2 线段漏确认，完整闭环修复）暴露四个结构性失效，
> 本文先批判原四修方案，再给出收敛契约修订版。

***

## 1. 背景：审计发现的四个失效

| #       | 现象                                                                       | 数据证据                             |
| ------- | ------------------------------------------------------------------------ | -------------------------------- |
| E1 效率   | 单 turn 64 次迭代、output 103K tokens、11 次成本提示全部被无视，靠"已运行 64 次仍未收敛"强提示才收尾     | session-1788545064755 · usage 汇总 |
| E2 写侧   | `[SESSION_SUMMARY]` 标记 0 次出现；运行时 digest 无"会话总结"段；外部手动沉淀的结论被运行时 digest 覆盖 | management\_brain/\*.md 两次生成对比   |
| E3 沉淀覆盖 | 外部直写 `management_brain/` 被收尾重写覆盖；同批写入 decision\_log.db #62 未被覆盖          | 02:26 手动版 → 02:34 运行时版           |
| E4 读侧   | 模型开场 session\_search 两次失败（fts5 语法错 / 中文不可命中）；首 turn 无历史结论注入，知识接力归零       | jsonl 记录 12-19 条                 |

分类：E1/E2 是"停止与归档的语义判断"缺位；E3 是持久层写者竞争；E4 是检索通道损坏（非"模型不知历史存在"——它实际检索过两次）。

## 2. 原四修方案的批判性评估

### 2.1 方案1：判据规则化（充分性契约）——主权错配，效率可能反噬

- **批判 A1**：探索型任务判据不可预定义。"回归通过"≠"根因找到"，规则的表达能力低于上下文；判据只能落到"窗口 3 段/测试通过"这类表面信号，对调查类任务产生假阳/假阴。

- **批判 A2**：判据过严 → 早收 → 质量损失 → 返工，总效率下降；判据机械 → 模型为满足判据取巧（选最便宜路径），target function 被 hack。

- **批判 A3**：核心自我矛盾——判据质量与模型上下文能力成正比，但设计初衷恰是"摆脱模型"。

### 2.2 方案2：确定性聚合归档——把结论降级成字段

- **批判 B1**：decisions 表字段（signature/root/solution/verify）承载不了模型在完整上下文中的精炼评估（如"恢复 3 段而非 5 段、端点待校准"的跨数据判断）。聚合 = 内容降级，是 recent\_transcript 尾部截断教训的加强版。

- **批判 B2**：大量会话无 log\_decision（聊天/探索/分析），聚合源为空 → digest 退化回"失败模式+成本"两段，E2 未修。

### 2.3 方案3：库为权威——信任破坏比覆盖更严重

- **批判 C1**：放开外部直插 decisions = 任何进程可伪造 verify\_count/success\_rate（审计写 #62 时即编造了 verified 度量），污染生产检索源，且污染不可见（digest 覆盖至少可对比）。

- **批判 C2**：decisions 表职责膨胀（失败捕获+决策+归档），search\_past\_decisions 中文语义本已弱，schema 演化破坏渲染。

### 2.4 方案4：入口主题匹配——治错病灶

- **批判 D1**：会话实际已主动检索两次 session\_search——E4 根因是**检索通道损坏**（fts5 非法词 + 中文不可命中），非"模型不知历史存在"。主题注入治不了坏通道。

- **批判 D2**：关键词重叠需中文分词，runtime 无此能力，仅 ASCII/n-gram 召回极低；松散匹配误报 → 注入误导上下文 → 模型向历史方向收缩 → 净变差。

### 2.5 效率影响矩阵（原方案）

| 方案      | 直接成本         | 质量风险               | 净效率   |
| ------- | ------------ | ------------------ | ----- |
| 1 判据规则化 | 预置规则成本低      | 早收/取巧 → 返工         | 可能下降  |
| 2 确定性聚合 | 近零           | digest 降级 → 下游检索变多 | 打平/略降 |
| 3 库为权威  | 低            | 数据可信度污染            | 打平    |
| 4 主题注入  | 首 turn 一次小文本 | 误报误导               | 可能下降  |

结论：四修净效果不提升甚至下降，违背"解决 E1"初衷。

## 3. 根因再分析：主权错配

E1/E2 的共同结构：运行时握住全部客观状态（目标、工具结果、测试返回值、决策记录、用量），却从不拿它们与"该停了吗/该归档什么"做确定性比对；所有语义判断都依赖模型在高 token 燃烧语境下的自愿文本行为（收敛靠自觉、归档靠标记）。

**正确的职能分配**：

- **模型 = 语义持有者**：持有完整上下文，能判断"任务是否完成、结论是什么、剩什么待办"——这是它的强项，不应被规则替代（打脸方案1），也不应被文本提示委托（现状失效）。

- **运行时 = 事实持有者**：持有确定性信号（pytest exit code、判别实验输出、窗口段数对比、成本数字），能精确校验"声称是否成立"，但不应替模型判断语义（方案1的病）。

> 收敛契约原则：**语义判断由模型声明，事实校验由运行时执行**。
> 运行时负责"逼出声明 + 校验声明的可验证残留"，模型负责"用全部上下文产出声明"。
> 双方各司其职，都不做对方该做的事。

***

## 4. 修订方案：收敛契约（Convergence Contract）

### 4.1 机制总览

```
turn 循环
  │
  ├─ 运行时盯"收敛信号"（客观门控，零 LLM）：
  │     · 工具结果含成功信号（pytest 0 passed / 判别实验输出 / 目标完成关键词）
  │     · 成本触及软阈值（默认 15K / 25K output，见 4.3）
  │     · 模型文本已多轮无新证据（近似中断检测）
  │     └─ 任一命中 → 注入【收敛声明】提示（轻量，非"别浪费token"，而是要求结构化声明）
  │
  ├─ 模型输出【收敛声明】（~150-300 token，turn 底部一次）：
  │     claimed_complete / evidence / conclusions / todos / can_stop
  │
  ├─ 运行时【事实校验】（纯规则）：
  │     claimed_complete=true 且 can_stop=true
  │       → 校验 evidence 引用的客观信号是否存在于本会话 tool history
  │            ├ 通过 → 强制停止：禁止新工具调用，交最终答复
  │            └ 不通过 → 注入"声称完成但证据缺失（缺 xxx）"，继续
  │     claimed_complete=false 且成本 > 硬阈值（分级 45K/60K，见 4.3）
  │       → 运行时强制中断，输出部分结论 + 明确未完成项（保底，防无限燃烧）
  │
  └─ 收敛声明直接进归档（确定性，见 4.4）
```

### 4.2 收敛声明格式（模型输出，注入提示引导）

```
[收敛声明]
goal: <任务目标一句话>
claimed_complete: true | false
evidence: <支撑声称的客观信号，如 "regression 11 passed, exit 0"> 
conclusions: <≤5 条，- 列表>
todos: <未完成项，- 列表；空则 "无">
can_stop: true | false
```

字段语义：

- `claimed_complete` 与 `can_stop` 拆开：模型可"声称有结论但需用户确认后继续"（如本案例等用户裁决方案 B）。

- `evidence` 是校验的关键输入——运行时只认本会话 tool history 里真实存在过的信号，不认描述。

- 触发时机：以软阈值档位为驱动——15K 首次、25K 二次（见 4.3），同档至多注入一次（"一次"指单档上限，非会话总量）；信号命中是触发判据而非累加器。单会话总注入上限 <5，与 4.6"×触发次数（<5）"口径一致。**不做每轮 tool 循环强制**（避免 token 增量失控）。

### 4.3 阈值与门控（默认值，env 可覆盖）

| 参数            | 默认                 | 说明                                        |
| ------------- | ------------------ | ----------------------------------------- |
| 收敛软阈值         | 15K output         | 首次注入声明提示                                  |
| 收敛软阈值 2       | 25K output         | 二次注入（若未收敛）                                |
| 硬阈值           | 60K output（Architectural 档） | 运行时强制中断并出部分结论；分级：Diagnostic 45K / Architectural 60K，Simple 不开契约（§6.2） |
| evidence 校验通过 | 信号存在于 tool history | 例如 stdout 含 "11 passed" 且 is\_error=false |

E1 实例回放：本案例软阈值 15K 处即注入声明 → 模型产出声明（含 evidence）→ 但 92K 前模型持续声称进行中 → 运行时在"测试通过"信号落地后再次注入 → 模型声明 complete=true / evidence="regression 11 passed" → 校验通过 → 强制停止于 \~95K（而非被逼到 103K）；若期望收紧，硬阈值按任务复杂度分级（Diagnostic 45K / Architectural 60K，复用既有 TaskComplexity；Simple 不开契约，见 §6.2）。

### 4.4 归档：收敛声明 → digest（确定性，废除标记依赖）

- digest"会话总结"段 = **收敛声明的 conclusions + todos**（模型用完整上下文产出，字段级复用，无 LLM 提炼通道、无需标记解析）。

- `[SESSION_SUMMARY]` 标记机制降级为兼容路径，不再是主通道；主通道 = 收敛声明字段。

- 文档型 digest 保持"\_确定性渲染 + 派生视图"：`render_digest` 吃（失败模式 / usage / 收敛声明字段 / decisions 表本会话记录），输出幂等。

- 外部沉淀（审计/人工）**只准写 decisions 表**，且必须带 `knowledge_source` provenance 标记；禁止裸 INSERT 伪造 verified 度量（验证信号仅由运行时在校验通过后写 true）。

### 4.5 检索通道修复（E4 真解，替代方案4 的主题注入）

不做入口主题匹配启发式。修既有通道（session\_search / search\_past\_decisions 同一 FTS 底座）：

1. **FTS5 中文检索**：tokenizer 评估换 trigram（CJK 可命中），或 SQL 层加"UTF8 规范化 + LIKE"兜底（与既有 escaping 白名单机制同源，见 lessons: fts5 非法词转字面短语）。
2. **fts5 非法词兜底**：查询词含 `.`/`-`/`+`/`@` 等或整句分词失败 → 自动转双引号字面短语再查（既有机制，扩展到中文句）。
3. 校验标准：`MATCH '漏确认'`（原返回空）修复后应命中 #62/#63 或其他含词记录。

### 4.6 效率评估（修订版）

| 项目     | 成本                         | 说明                        |
| ------ | -------------------------- | ------------------------- |
| 收敛声明输出 | \~150-300 token × 触发次数（<5） | 门控触发，非每轮；增量 ≈ 1-2% output |
| 事实校验   | 零 LLM                      | 纯规则 scan tool history     |
| 强制停止   | 节省 E1 尾部 10K-60K 无谓 output | 本案例 60K→103K 段直接切除        |
| 归档     | 复用声明，省独立提炼通道               | 试点本就为省此通道                 |
| 检索修复   | 一次性工程                      | 后续会话 FTS 命中率↑，重复侦察↓       |

净效果：收敛先于成本燃尽、归档确定性成立、跨会话检索可达 → **效率净提升 + 质量不降级**（保留模型语义判断，不做规则替代）。

| Phase | 内容                                            | 改动面                                                                                   |
| ----- | --------------------------------------------- | ------------------------------------------------------------------------------------- |
| P1    | 收敛契约核心：信号门控 + 声明提示注入 + 声明解析 + 事实校验 + 强制停止     | `runtime/src/conversation.rs` + prompt 注入区 + 新增 `runtime/src/convergence.rs`（纯函数，可单测） |
| P2    | 归档改造：`render_digest` 吃收敛声明字段；标记机制降级兼容         | `runtime/src/management_brain.rs`                                                     |
| P3    | 检索修复：FTS5 中文 tokenizer/兜底 + fts5 非法词转字面短语     | session\_search / FTS 索引层                                                             |
| P4    | 持久层规范：外部沉淀只走 decisions（provenance 强制），文档化写库规范 | 本设计文档 §4.4 即为规范载体                                                                     |

验收标准（以 E1 同款任务复测）：

1. output 收敛于 <45K（基线 103K），且最终答复含完整结论与测试证据（证明非早收）。
2. digest 含"收敛总结"段（= 声明 conclusions），不再依赖标记。
3. 新会话 `session_search` 中文句可命中本会话结论。
4. 打回率 ≤20%（N≥5 轮回归，口径与基线见 §6.1；基线 76.5% → 目标的下降量即契约净收益）。

验收统一口径：第 1-3 条测"收敛先于成本燃尽 / 归档确定性 / 检索可达"，第 4 条测"停止质量"；四条全部通过方判定 P1-P3 验收完成。

## 6. 三未决问题的设计定稿

### 6.1 假阳性诱导：四层反诱导结构（信号多样性 / 子项覆盖 / 打回率埋点 / 验收窗口）

诱导风险的真实形态不是"模型故意撒谎"（高燃烧下模型仍保持诚实，实证：E1 案例 103K output 时仍主动承认"3 段非 5 段"），而是两种认知性假阳性：

- **权宜性声称**：被门控反复推进时提前收敛（信心不足受压力收敛）；

- **确认偏置**：把"测试过了"解读为"任务完成"（回归通过 ≠ 根因验证过）。

对策（不依赖文本恐吓，已被证明无效）：

1. **信号多样性门槛**：`evidence` 必须含 ≥2 种不同 signal\_type（见 6.2 注册表）。单信号声称不判 pass，直接掐断"只见测试不看判别实验"的确认偏置。
2. **子项覆盖比对**：声明 `conclusions` 与任务立案的 goal/tracker 待办做关键词覆盖检查（零 LLM），防"有证据但只做一半"。
3. **打回率埋点**：声称完成 → 停止后 3 条内被用户重新打开任务（"继续/不对/你没做完"）= 一次打回。统计进 data。**验收指标**：E1 同款任务回归 N≥5 轮，打回率 ≤20%，超阈值回退"多样性门槛"强度（指标与 §5 验收标准第 4 条同源，验收以 §5 汇总表为准）。

**埋点口径（2026-09-05 已用历史会话验证）**——三层词表 + 两类剔除，避免把"同域新问题报告/自澄清"误计为打回：

- 强打回词（STRONG）：直接质疑上次结果/要求重做/未解决/无输出——"不对/错了/重新执行/重新设计/为什么还没有/卡住了/并不构成…"；

- 弱打回词（WEAK）：双义词（有问题/缺/漏…），计宽口径；

- 疑似推进（FORCE）："再跑/继续修/还没有…"单独成桶不计入打回；

- 剔除前缀：自澄清（"是我/我误/明白了…"）、新域报告（"我看到/关于/现在的…"）。

- 已知误判：含有"是不是"的疑问句可命中"不是"（约 15% 假阳），验收时按 x0.85 修正或引入疑问句判断。

**基线（无契约现状，扫描两侧历史会话主文件）**：

| 口径       | 数值                  |
| -------- | ------------------- |
| turn 总数  | 17                  |
| 强打回      | 13（76.5%，修正约 64.7%） |
| 宽口径（强+弱） | 82.4%               |
| 疑似推进     | 3（17.6%）            |

结论：诊断/架构级任务在无契约状态下，模型收尾后约 **2/3 概率被打回**（用户重新介入纠错或要求重做），即"自发收尾"质量置信度仅约 1/3——这正是收敛契约要解决的靶心；验收目标（≤20%）相对基线的下降量即契约净收益。
4\. **验收窗口**：强制停止后允许用户引导修正，不算失败，避免误伤真收敛。

### 6.2 信号注册表：按任务相位设计，按复杂度开启

收敛契约**不适用于所有任务**：Simple/问答类 output 天然小，开启为过度设计。按 TaskComplexity 分级：**Simple 不开，Diagnostic/Architectural 开**（复用既有复杂度分级）。

| signal\_type       | 捕获范围                   | 可校验字段                  | 适用相位  |
| ------------------ | ---------------------- | ---------------------- | ----- |
| test\_success      | Bash stdout "N passed" | exit\_code=0           | 修复/回归 |
| experiment\_output | 判别/对照实验输出块             | 含对比表/数值                | 根因调查  |
| file\_produced     | write\_file 结果         | is\_error=false + 文件存在 | 交付/分析 |
| evidence\_cited    | 会话引用真实数据源              | 引用与声明一致                | 调查/探索 |
| materials\_closed  | 探索覆盖面                  | 新增未读材料集合为空             | 探索/分析 |

调查/探索类任务靠 `experiment_output + evidence_cited + materials_closed`，不依赖测试信号。多样性要求 ≥2 类（与 6.1 联动）。

### 6.3 强制中断补偿：确定性收割，不依赖模型

硬阈值触发时模型不可信、成本已高——补偿**禁止让模型补完**，改由运行时确定性收割已产出成果：

1. **收割器（harvester）**：复用 task\_state 结论门槛提取逻辑（零 LLM），从 tool history 提取：

   - 已确证事实：关键工具结果（判别实验输出 / 测试通过记录 / 文件产物）；

   - 未完成清单：tracker 未闭环项 + task\_state.todos；

   - 结论候选：强判定句（规则提取，**诚实标注来源"规则提取，待人工确认"**，不冒充模型声明）。
2. **interrupted 标记**：写入 digest，新会话首 turn **注入优先级高于正常 digest**——被打断任务自动成为最高优先续接对象（与 task\_state"活性任务优先"原则一致）。
3. **续接锚点**：会话 id + 停止位置 + 建议新会话首句（如"继续 session-xxx 的 xd\_l2 验证"）。

### 6.4 机制联动

6.1 的多样性门槛与 6.2 的注册表是同一机制（signal registry）；6.3 收割器复用 task\_state 提取。三个未决收敛为\*\*"信号注册表 + 打回率埋点 + 确定性收割"\*\*三项补充，改动面仍集中于 `convergence.rs`，与 P1 同批实施。
